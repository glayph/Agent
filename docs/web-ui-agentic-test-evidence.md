## Test environment

The authenticated Web UI was served at `http://127.0.0.1:18800`. The selected model was `lfm2.5-local-1.2b`, backed by a local llama.cpp server at `http://127.0.0.1:39200/v1`. ## Initial failure observed in Web UI

The first benchmark was a safe multi-step software-engineering task. Although the UI displayed the local model, the run repeatedly fell back to Gemini and showed: `The gemini credential was missing or rejected. Add a valid API key in Models/Credentials, then retry.` No requested artifact was produced. A separate UI attempt also exposed a missing `/api/goals` route, but that route was unrelated to the actual chat benchmark because the user clarified that `/goal` was the task directive, not an Agent Miki feature.

## Root causes identified

The local model's friendly display label was being sent where the provider-facing canonical model identity was required. The launcher also failed to hydrate stored local-model configuration into the core runtime, and readiness checks only considered a core-managed process, not a healthy externally started llama-server. Finally, the deterministic file parser did not recognize the UI's backtick-quoted multi-file form and stripped punctuation from explicitly exact content.

## Remediation applied

The bundled llama-server path was added to runtime discovery and the model manager. Backend model metadata now exposes a canonical `runtime_model`; the frontend sends that canonical identity while preserving the friendly display label. Launcher startup hydrates stored models, and local model resolution synchronizes local runtime state without forcing remote fallback. External successful health probes are remembered for readiness checks. The deterministic parser now accepts backtick-quoted file paths/content, preserves exact punctuation and JSON syntax, and has a regression test.

## Final Web UI task

The Web UI showed `File Write — Completed`, followed by `File Read — Completed` twice, and displayed links for `README.md` and `result.json`. The final filesystem check reported exactly two files—`README.md` and `result.json`—with no extra file. Byte-level inspection confirmed the exact requested contents.
