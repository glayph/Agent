## Final privacy hardening

The Live Node View previously retained a raw `output_preview`/error rendering path in its selected-activity panel and expanded graph nodes. Those renderers now show only `activitySummary(node)`, `activityTitle(node)`, and `activityStatusLabel(node.status)`. Technical command output, JSON, terminal text, raw tool labels, and internal status strings are no longer rendered in the user-facing activity UI. The raw fields remain available only inside the event/state contract so real backend events can continue to drive status transitions.

The frontend lint, 12 test files with 43 tests, and production build all pass after this change.

## Second requirement audit — 2026-08-19

The connected experience was re-audited against the latest brief. Chat now includes a compact `LiveActivityStrip` inside the existing conversation layout. It is populated from the latest real monitor run only, uses the shared human-readable activity-copy helpers, shows active/retrying/completed/failed state with lightweight state-bound icons, and exposes no raw command, arguments, JSON, API request, or terminal output.

Chat activity selection now selects the shared monitor node and navigates to `/agent/monitor`. The Node View conversation link preserves the selected node before returning to `/`, where the corresponding Chat activity receives a temporary focus state. ReactFlow node clicks and connection clicks both select the same shared activity state.

The monitor protocol remains backend-event-driven. Nodes are created only from `node.run_start`, `node.spawn`, `node.update`, `node.complete`, and `node.run_end` messages. Connection animation is derived from stored edge state; incoming flow stops when the target activity settles, and failed activities stop downstream flow. No random or timer-generated activity is used.

Final frontend validation after this audit: lint passed, 12 Vitest files passed, 43 tests passed, and production build passed. Browser smoke navigation confirmed Chat → Live Activity → Chat remains functional. The current smoke browser had zero live events after reload, so no artificial event was injected; the previously approved real backend run remains the source used for live event verification.
