## 2026-08-19 08:47 UTC — supervisor hardening

The supervisor recovery test terminated the gateway child. The top-level supervisor detected the exit, persisted `restartCount: 1`, waited with exponential backoff, and brought up a new gateway/core tree; the runtime then returned healthy. A duplicate-supervisor test initially exposed a lock bug: the active-PID error was thrown inside its own probe catch block, allowing the duplicate to bypass the lock. The lock implementation was corrected, the runtime tree was cleanly restarted, and a second launch now exits with `another 24/7 supervisor is already running` while the original process tree remains intact.

The supported commands are `npm run runtime:24-7` for the persistent process and `npm run runtime:24-7:check` for a non-starting build/path check. State is persisted in `data/24-7-supervisor.json` and the active lock in `data/24-7-supervisor.lock`.
